## Подключение платежей — внешний блокер

В списке товаров по-прежнему показано **«Покупки не подключены»**.
Профиль разработчика: монетизация «Подключена», единая лицензионная схема
«Не подключён»; переход к ЕЛС недоступен из-за действующего договора РСЯ.
Статус «Активная» у отдельных товаров не означает подключения платежей.

По официальной инструкции для этой схемы требуется запрос в поддержку
после акцепта оферты РСЯ. Запрос отправлен пользователем; идёт переписка
с поддержкой по условиям подключения. Договор и реквизиты агент не менял.
До подключения нельзя проверить живой каталог и сценарии тестовой оплаты.

Подготовленный запрос:

- Получатель: `games-partners@yandex-team.ru`
- Тема: `Подключение инап-покупок — Ruinstead, ID 619868`

```text
Здравствуйте!

Прошу подключить инап-покупки для игры Ruinstead, ID 619868.
Монетизация в консоли подключена. Каталог из 15 товаров создан,
но раздел инап-покупок показывает «Покупки не подключены».

Ссылка на игру в консоли:
https://games.yandex.ru/console/application/619868

Спасибо!
```

После подтверждения подключения: настроить тестовый логин, проверить каталог,
отмену покупки, начисление и расходование квитанции, восстановление постоянного
товара и повторную обработку незавершённой покупки. Реальные платежи не выполнялись.
В коде повторная обработка есть, постоянные покупки не консумируются.
Первоначальный аудит 2 октября обнаружил дефект сохранения расходуемых покупок: локальный
`GameStateStore.save()` и облачный `flushYandexCloudSave()` подавляют ошибки.
`grantPurchase()` после этого продолжает `consumePurchase()`, который удаляет
квитанцию без возможности восстановления. Если облако не сохранило покупку,
а локальные данные потеряются, восстановить её через SDK уже нельзя.
Тест с искусственной ошибкой `player.setData()` подтвердил: flush завершается
успешно для вызывающего кода, хотя запись отклонена. При повторной обработке
уже начисленного токена блок сохранения также пропускается.
До оплаты нужно требовать успешного сохранения перед консумированием и
повторять сохранение для отложенной квитанции без повторной выдачи товара.
`node scripts/platform-release-sanity.mjs` проходит; текущие fixtures не
проверяют этот сбой в полном обработчике выдачи. Код в ходе аудита не менялся.

### Исправление 2 октября после аудита

Дефект исправлен в локальном production-коде. До консумирования требуется
успешная запись прогресса и purchase token локально и в облако. Для уже
начисленных токенов сохранение повторяется без повторной выдачи. Постоянные
товары не консумируются; их подтверждённое владение также сохраняется.
Облачные записи сериализованы и используют снимки состояния; предыдущая
запись не может завершиться после новой и стереть её. Если чтение облака
не удалось, неизвестный прогресс не перезаписывается.

Новый `scripts/purchase-persistence-sanity.mjs` включён в `check:release` и
проверяет настоящий обработчик `WorldScene`, `GameStateStore`, облачное
сохранение и YandexPurchaseProvider. Покрыты ошибки обоих локальных ключей,
чтения/записи облака и consume, повторный запуск, потеря локальных данных,
одновременные callbacks, отдельные покупки, permanent bundle, самоцветы,
продление ad-free и блокировка второй оплаты до завершения первой.
Все ответы SDK в этой проверке — fixtures. Реальной оплаты не было.

По разделу «Выплаты» официального руководства самозанятый может подключать
покупки, однако договор на них оформляется как с физическим лицом.
Для текущей схемы без ЕЛС предусмотрен запрос после акцепта оферты РСЯ.

Подтверждение: `yandex-iap-catalog-saved.jpg` в папке визуализаций
`ruinstead-2026-10-01`.
