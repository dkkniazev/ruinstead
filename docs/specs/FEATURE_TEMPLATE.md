# Feature

## Status

Draft / Approved / Implemented / Deprecated

Select one status. When instantiating, omit irrelevant sections rather than
filling them with generic boilerplate. Draft proposals do not override current
contracts; implementation notes never override requirements.

## Problem

Observed evidence and affected user/workflow; link the actual implementation.

## Goal

The intended outcome and its scope.

## User-visible behavior

What the player sees/does and what changes.

## Current behavior

Confirmed current contract; distinguish Unverified facts.

## Required behavior

The intended contract after this feature, separate from current behavior.

## Non-goals

Explicitly excluded changes.

## Invariants

Existing behavior that must survive.

## Functional requirements

Concrete inputs, transitions, outputs and failure behavior.

## Edge cases

Relevant unavailable/repeated/cancelled/invalid/boundary cases.

## Data / persistence implications

State ownership, compatibility, migration/defaults, reward/spend idempotence.

## Platform implications

Providers, SDK callbacks, lifecycle and local fallback.

## UI / input implications

Desktop/touch interaction, range/prompts, focus/pause and availability.

## Localization implications

New display strings/metadata, stable IDs, RU/EN validation.

## Performance considerations

Concrete workload/resource risk and validation; no unsupported targets.

## Security / abuse considerations

Relevant replay, invalid input, duplicate reward and trust boundaries.

## Acceptance criteria

Observable pass/fail statements, tied to requirements. For visuals, name the
camera/state/pair and reviewable silhouette/attachment/readability outcomes.
Avoid “looks better”, “works properly” or “improved UX” without a defined scenario.

## Automated validation

Exact existing commands and meaningful new regression cases; distinguish fixtures.

## Manual validation

Exact scenarios, build/save/device context and evidence required for judgment.

## Implementation notes

Optional source references/options. Describe mechanics in execution plans when
multi-stage; never let these notes silently change the feature contract.
