# Исследование перед внедрением SDD · 2026-10-02

Исследован текущий рабочий каталог, включая незакоммиченный визуальный проход.
Базовый HEAD: `35f546e`; выводы не описывают только этот коммит или загруженный ZIP.
README не использовался как доказательство реализации. Изучены `src`, package scripts,
все семейства sanity-скриптов, CI, упаковка, текущие отчёты и история изменений.

## Подтверждённая реализация

- TypeScript/Vite, Phaser для сцен/физики, Three.js для мира; DOM HUD.
  Источники: `src/main.ts`, `src/game/config.ts`, `src/scenes/WorldScene.ts`,
  `src/scenes/HudScene.ts`, `src/game/render3d/WorldPresentation3D.ts`.
- Восемь полигональных регионов, 40 обычных видов, 24 босса, 120 пачек
  по 3–8 мобов и три элиты каждого вида. Пять семейств оружия, пять слотов,
  уровни/звёзды/редкости, автоатаки, сбор при aggro, сундуки по E.
  Источники: `ReleaseRegionMap.ts`, `ReleaseWorldContent.ts`, `EnemySystem.ts`,
  `WeaponInventory.ts`, `WorldInteractions.ts`; проверки мира/игровых регрессий.
- Сюжетная цепь из 23 ключевых заданий, независимые подготовительные задания,
  здания/производство, бестиарий, уровни 1–50, облики/мастерство/магазин.
  Источники: `QuestDirector.ts`, `CityBuilderSystem.ts`, `PlayerLevelBalance.ts`,
  `PremiumSystem.ts`; `scripts/campaign-sanity.mjs`.
- Schema 29, локальная/облачная запись, миграции, квитанции покупок с сохранением
  до consume, SDK lifecycle и RU/EN. Источники: `GameStateStore.ts`,
  `YandexCloudSave.ts`, `WorldScene.applyPurchaseReceipt`, `YandexPlatform.ts`,
  `src/i18n`; `check:release` на fixtures.

## Частично реализовано

- Покупки реализованы в клиенте, но подключение платежей и живой платёжный QA
  не подтверждены: `docs/IAP_CATALOG.md`, `docs/RELEASE_READINESS.md`.
- Визуальная система охватывает каталог, художественный проход ещё не принят:
  `docs/VISUAL_BACKLOG.md`, модели/ауры/подготовленные сетки в `render3d`.
- Desktop и touch работают; полный тест физических устройств/слабого ПК и
  нового сохранения до финала остаётся непроверенным по release-отчётам.

## Документировано, но не реализовано

- Ранний README описывает будущие этапы, свободное расширение и более широкое
  поселение. В runtime городская прокачка ограничена четырьмя зданиями;
  `infirmary`/`gate` есть в модели сохранения, отдельная прокачка этих зданий
  в `CityBuilderSystem` отсутствует. Не выдавать наличие поля за функцию.
- TV определяется SDK, но отдельного TV/remote input нет.
- Полноценная физика ткани/ragdoll и система заклинаний игрока отсутствуют;
  текущие анимации процедурные, оружие игрока ближнего боя.

## Реализовано, но нет актуального общего контракта

- Пять секунд полного лечения на базе; вес монет 0 с выпадением при смерти;
  потолок героя 20 улучшений/рюкзак 1000; лимит 32 эквивалентных копий до
  fusion и reroll того же rarity; отдельные optional quests.
- Непрерывные полигональные границы/навигация, wind-up и roaming, стабильные
  ресурсные точки, немодальный бонус сундука, подготовленные скульптурные сетки.
  Подтверждены кодом и скриптами, сведения разбросаны по отчётам.

## Неоднозначности и новые результаты

- Первый `check:release` остановился на импорте реальной сцены:
  `Error: No clear formation for magma-hound group 1`.
  `EnemySystem.buildEnemySpawns()` использует случайный выбор и вызывается
  при импорте через `ALL_SPAWNS`. Повторный запуск прошёл. Частота и семя сбоя,
  а также воспроизведение в браузере — **Unverified**. Это риск запуска;
  повторный PASS не закрывает проблему.
- `check:polish` прошёл 24 заданных seed, это не доказательство безопасности
  любого случайного расклада. Остальные запущенные проверки: `balance`,
  `check:campaign`, `check:world`, `check:gameplay`, `check:regressions`, `check:art`
  — PASS. После записи SDD typecheck/build и docs validator с negative fixtures
  тоже прошли; Vite предупредил о крупном JS chunk (~745 КБ gzip).
- `.github/workflows/ci.yml` пока не запускает `check:release`, `check:campaign`
  или отдельную проверку переводов. `release:pack` сам не запускает все игровые gate.
- Вложенный `ruinstead` — gitlink (mode 160000), отдельный старый checkout;
  корневой npm/Vite не включает его. Назначение — **Unverified**, не менять.
- Аналитика — только DOM-событие `ruinstead:analytics`, внешний сборщик не найден.
- Forge proximity проверяется UI при открытии/upgrade; обработчики upgrade/fusion
  в сцене не перепроверяют дальность. Не путать это с серверным/сценовым запретом.
- Safe-zone ветка отключает primary, но orbitals обновляются раньше неё. Рывок
  сам не добавляет damagePlayer immunity; контракт не приписывает её движению.
- Два из четырёх названий игровых референсов не восстановлены. Доступны
  Hero Path RPG / XP Hero; собственная обложка их не заменяет.

## Решение

создать небольшую связанную систему доменных спецификаций и проверку ссылок/команд.
Обновить существующий AGENTS, статус, drift и roadmap. Следующий предлагаемый
milestone — воспроизводимость генерации пачек и надёжность release gate;
его реализацию в рамках bootstrap не начинать. Gameplay и runtime-ассеты сохранить.
